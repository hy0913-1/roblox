# 프레디 격투 게임 — 기획 및 개발 인수인계

작성: 2026-09-28 (한국 시간)
가칭: Freddy Fight. 정식 게임명 미정.

## 0. 다음 대화에서 바로 시작하기

아래 문장과 이 파일을 함께 전달한다.

> 프레디 격투 게임 개발 시작하자. 첨부한 FREDDY_FIGHT_HANDOFF.md를 읽고 기존 기획을 유지해줘. Roblox Studio 연결 가능 여부를 실제 도구로 확인하고, 가능하면 열린 프로젝트를 확인한 뒤 적용해줘. 직접 연결이 불가능하면 Studio에 적용할 수 있는 스크립트와 정확한 설치 위치를 만들어줘. 첫 목표는 임시 캐릭터 2명으로 이동·잽·강펀치·가드·대시·카운터·KO가 작동하는 1대1 테스트야. 새 아이디어를 늘리기보다 먼저 플레이 가능한 전투를 만들고, 실행하지 않은 테스트를 통과했다고 말하지 마. UBG는 공개 자료로 전투 감각을 참고하되 모션이나 코드를 무단 추출하지 마.

### 현재 실제 상태

- 기획만 완료. 코드, Studio 프로젝트, 모델, 리깅, 애니메이션은 아직 준비·검증하지 않았다.
- Studio MCP 연결은 확인하지 않았다. 연결됐다고 가정하지 않는다.
- UBG(Untitled Boxing Game)는 사용자가 지정한 참고작이다. 이 대화에서는 실제 영상이나 시스템 자료를 조사하지 않았다.
- 오늘은 사용자가 컴퓨터를 꺼둔 상태여서 기획 정리만 요청했다.
- 다른 대화의 게임 프로젝트와 별개인 신규 Roblox 프로젝트다. 기존 프로젝트를 덮어쓰지 않는다.

## 1. 핵심 방향과 결정 수준

### 사용자가 제안·동의한 핵심

- Roblox에서 만드는 프레디의 피자가게 캐릭터 격투 게임.
- UFC라는 발상으로 시작했으며, 첫 제작은 UBG를 참고한 주먹 중심 1대1 전투.
- 기본 전투는 진지하고 손맛 있게, 필살기는 과장되고 우스꽝스러운 반칙.
- 캐릭터: 프레디, 보니, 치카, 폭시, 스프링보니 계열.
- 캐릭터마다 작은 전용 스킬 1~2개. 현재 각 1개 아이디어가 있다.
- 스프링보니는 다운마다 스프링트랩 → 스크랩트랩 → 번트랩으로 변화.
- 품질 낮은 자체 제작 모션에 대한 우려가 크다. 기존에 잘 만든 사용 가능한 모션을 확보하고 게임에 맞게 조정하는 방향에 동의했다.

### 대화에서 나온 설계 초안 — 테스트 후 조정

- 공격·회피에 배터리를 쓰고 쉬면 회복. 고갈 시 과열되지만 걷기와 기본 방어는 가능.
- 약공격, 강공격, 가드, 회피, 카운터가 기본. 잡기·발차기·바닥 그래플링은 후순위.
- 외장 파손은 우선 시각 효과로만 구현.
- 스킬 쿨타임 8~14초, 필살기 연출 4~5초는 확정 수치가 아니다.
- 부활 체력, 다운 횟수, 라운드 수, 승리 조건의 세부 규칙은 아직 미정.
- 캐릭터별 능력치, 과열 효과, 가드 파괴 시간, 카운터 배율, 필살기 충전량도 미정.
- 성장 능력치 없이 스킨·등장·도발 위주 해금은 제안 단계.

## 2. 기본 전투의 목표

잽으로 거리와 반응을 떠보고, 헛친 강공격을 피한 뒤 카운터를 넣는다. 가드만 유지하면 가드가 깨지고 회피를 남발하면 배터리가 부족해지는 상호작용을 목표로 한다.

- 공격 전 준비 동작, 타격 순간, 공격 후 빈틈을 구분한다.
- 캐릭터 외형이 달라도 피할 수 있는 동작과 맞는 이유가 읽혀야 한다.
- 카메라, 타격음, 짧은 타격 정지와 피격 반응으로 금속의 무게감을 만든다.
- 큰 개그 연출은 등장·필살기·다운·휴식·승리에 배치한다.
- 일반 전투 중에는 시야와 조작을 과도하게 방해하지 않는다.
- 첫 버전은 KO까지 구현하고 복잡한 라운드/다운 부활 규칙은 이후 결정한다.

## 3. 캐릭터와 작은 스킬

명칭과 세부 효과는 초안이다. 사용자가 정한 스킬의 핵심은 유지한다.

| 캐릭터 | 격투 성향 초안 | 사용자 지정 스킬 | 구현 방향과 대응 방법 초안 |
| --- | --- | --- | --- |
| 프레디 | 묵직한 균형형 복서 | 마이크 집어던지기 | 직선 투척, 작은 피해와 짧은 경직. 옆으로 피하면 빈틈 노출 |
| 보니 | 긴 리치의 견제형 | 기타로 강력한 가드 | 잠시 정면을 강하게 방어. 사용 중 이동·공격 제한, 종료 타이밍에 빈틈 |
| 치카 | 버티며 접근하는 압박형 | 컵케이크로 공격 페이크 | 강공격과 비슷한 준비 동작 후 컵케이크가 위협. 피해는 없고 회피를 유도한 뒤 실제 공격 |
| 폭시 | 빠른 진입과 연타 | 빠른 속도 대시 | 접근·측면 이동. 자동 공격이나 무적 없이 방향 싸움으로 설계 |
| 스프링보니 계열 | 형태에 따른 변화 검토 | 소방도끼로 한 대 후려치기 | 큰 준비 동작 후 한 번 휘두름. 가드 피해 중심, 빗나가면 큰 빈틈 |

- 임시 스킬명: 마이크 투척 / 기타 가드 / 컵케이크 페이크 / 해적의 돌진 / 안전 점검.
- 치카 페이크는 진짜 공격과 구분할 작은 단서를 남긴다. 무조건 속게 만들지 않는다.
- 치카의 작은 스킬은 무피해 페이크, 필살기의 컵케이크는 실제 공격이라는 차이를 명확히 한다.
- 보니의 일반 가드와 기타 가드는 성능과 시각 효과를 구분한다.
- 폭시의 기본 회피와 전용 대시를 구분하고 무한 추격·도주 가능성을 점검한다.
- 두 번째 스킬은 아직 정하지 않았다. 억지로 추가하지 않는다.

## 4. 필살기

### 공통 초안

- 공격 적중, 정확한 회피, 카운터 등 적극적 플레이로 게이지 충전.
- 첫 타격은 회피 가능. 명중 확인 후 두 캐릭터가 맞물리는 전용 연출 진입.
- 빗나가면 게이지를 소비하고 빈틈이 생기는 방향.
- 연출은 짧게 유지하고, 생존 시 전투로 복귀한다.
- 일반 적중과 최종 KO의 마무리 연출을 구분할 수 있다.
- 로봇 외장·나사·스프링·불꽃으로 타격을 표현한다.

| 캐릭터 | 사용자 지정 핵심 | 연출 초안 |
| --- | --- | --- |
| 프레디 | 정전시킨 후 머리 물어뜯기 | 가까이서 잡기 성공 → 정전 → 오르골과 눈만 빛남 → 불이 켜지며 머리 외장을 와작. KO 시 외장만 입에 남고 내골격이 서 있음 |
| 보니 | 기타로 내려찍기 | 첫 타격 성공 → 공연 조명 → 크게 내려찍기 → 끊어진 기타 줄에서 ‘띠용’ |
| 치카 | 컵케이크 던지기 | 투척 명중 → 얼굴에 붙어 깨물기 → 치카가 쟁반으로 마무리 |
| 폭시 | 갈고리로 낚아채기 | 직선 갈고리 명중 → 끌어오기 → 반대편 바닥에 패대기 → 낚시 성공 효과음 |
| 스프링보니 계열 | 미정 | 소방도끼는 현재 작은 스킬이다. 이를 필살기로 바꿔 기록하지 않는다 |

임시 필살기명: 영업 종료 / 앙코르 사절 / 디저트 서비스 / 오늘의 월척.

## 5. 스프링보니의 4단계 다운/부활

핵심 순서는 반드시 유지한다.

**스프링보니 → 스프링트랩 → 스크랩트랩 → 번트랩 → 최종 KO**

| 현재 형태 | 쓰러졌을 때의 연출 초안 |
| --- | --- |
| 스프링보니 | 내부에서 철컥 소리 → 조명 깜빡임 → 스프링트랩으로 부활 |
| 스프링트랩 | 불이 붙음 → 소화기 분말이 화면을 가림 → 스크랩트랩으로 부활 |
| 스크랩트랩 | 심판이 끌고 가려 함 → 케이블이 몸을 다시 조립 → 번트랩으로 부활 |
| 번트랩 | 손가락이 다시 꿈틀 → “I always come—” → 심판이 멀티탭을 뽑아 최종 종료 |

밸런스 초안:

- 네 형태마다 다른 캐릭터 한 명 분량의 체력을 주지 않는다.
- 전체 체력 예산을 네 형태에 나누는 방향으로 검토한다.
- 부활의 무적·회복·시간 끌기까지 합친 실제 이득을 테스트해야 한다.
- 뒤 형태일수록 공격은 강하고 가드는 약해지는 방식은 선택 사항이다.
- 먼저 동일한 기본 뼈대와 모션을 공유할 수 있는지 검토한다. 형태마다 모델 구조가 다르면 추가 리깅 작업이 필요하다.
- 이 캐릭터는 기본 4명의 전투가 안정된 다음 제작한다.

## 6. 개그 연출 후보

아래는 핵심 전투 이후 추가할 후보이며 첫 버전 필수 항목이 아니다.

- 내골격 심판: 평소 엄격하지만 반칙 무기를 꺼내면 못 본 척 고개 돌리기.
- 소방도끼 항의: 스프링보니가 ‘소방용’ 표시를 보여주면 심판이 납득.
- 휴식: 충전기에 연결하고 직원이 뚫어뻥으로 찌그러진 얼굴 수리.
- 정확한 회피: 눈알만 주먹을 따라 움직임.
- 더블 KO: 둘 다 폐기물 수레에 싣기.
- 승리: 승자는 생일 축하 공연 자세, 뒤에서는 패자를 끌고 나감.
- 폭시의 갈고리에 특제 글러브 씌우기.
- 일반 다운: 눈이 꺼졌다 재부팅 소리와 함께 다시 켜짐. 일어나기 연타는 피하는 방향.
- 스프링보니 소개 문구 후보: ‘내구성: 불량 / 서비스 종료: 불가능’.

## 7. 제작 도구와 모션 확보

- Roblox Studio + Luau: 맵, 조작, 전투, 멀티플레이.
- Blender: 필요할 경우 모델 수정, 공통 뼈대, 외장 부품 정리.
- Studio 애니메이션 편집기 또는 호환되는 제작 과정: 확보한 모션 적용과 보정.
- 이미지 생성 프레임은 3D 뼈대 애니메이션의 대체물이 아니다.
- UBG의 거리 싸움과 반응을 공개 영상 등으로 분석하되, 코드를 추출하거나 모션을 복제해 가져오지 않는다.
- 기존 복싱 모션은 사용·수정·Roblox 적용 조건을 확인한 뒤 확보한다. 구매나 의뢰는 사용자가 정한 예산과 승인 없이 진행하지 않는다.
- 모델과 모션의 뼈대 호환성을 확인한다. ‘구하면 바로 적용된다’고 가정하지 않는다.
- 적절한 모션이 없으면 임시 모션임을 표시하고 기능을 먼저 검증한다. 최종 모션 품질이 확보됐다고 주장하지 않는다.

### 최소 모션 목록

대기, 전후좌우 이동, 잽, 스트레이트/강펀치, 가드, 회피, 피격, 다운.
좌우 방향·피격 높이 등 필요한 변형은 실제 전투를 만든 뒤 산정한다.

필살기는 공격자와 피격자의 동기화 모션, 카메라, 효과음이 필요하다. 벽·링 가장자리에서도 서로 어긋나지 않아야 한다.

## 8. 개발 순서와 완료 기준

### 1단계 — 임시 캐릭터 1대1

작은 링, 두 참가자, 이동, 잽, 강펀치, 가드, 대시, 카운터, 체력·배터리 UI, KO·재시작.

완료 기준:

- 두 클라이언트에서 같은 승패와 체력이 보인다.
- 공격이 범위 밖의 상대에게 맞지 않고 한 타격이 중복 적용되지 않는다.
- 가드 방향, 회피 타이밍, 공격 후 빈틈이 작동한다.
- 공격 연타로 스태미나·쿨타임을 우회하지 못한다.
- KO 후 공격이 계속 들어가지 않고 다음 경기 상태가 초기화된다.
- 사용자에게 손맛을 확인받고 모션 문제와 판정 문제를 구분한다.

### 2단계 — 프레디 완성도 샘플

모델, 모션, 금속 타격음, 마이크 스킬, 정전 필살기, 다운 연출.
이 단계에서 최종 목표의 타격감과 개그 톤을 확인한다.

### 3단계 — 보니와 캐릭터 대전

보니 모델과 리치, 기타 가드, 기타 필살기. 프레디와 매치업 테스트.

### 4단계 — 치카·폭시

페이크와 투사체, 고속 이동, 컵케이크/갈고리 필살기 추가.

### 5단계 — 스프링보니 계열

4형태 모델, 다운 전환, 전체 체력 예산, 소방도끼, 멀티탭 KO.

### 6단계 — 확장

등장·휴식·관전·꾸미기, 필요 시 발차기와 잡기. 랭크전이나 상점보다 핵심 전투와 모바일 조작을 먼저 안정화한다.

## 9. 구현 인수인계 메모 — 개발 시 사용할 제안

아래는 아직 생성하지 않은 권장 구조다.

- ReplicatedStorage/Shared: 캐릭터·공격 설정과 공유 상태 정의.
- ReplicatedStorage/Remotes: 조작 요청 및 승인된 전투 결과 전달.
- ServerScriptService/Combat: 공격 가능 여부, 거리·방향·타이밍, 피해와 자원 검증.
- ServerScriptService/Match: 참가, 시작, 다운, KO, 재시작 관리.
- StarterPlayer/StarterPlayerScripts: 입력, 카메라, 모션 재생, UI 연결.
- 캐릭터별 모션 ID와 수치를 설정으로 분리해 임시 자산 교체를 쉽게 한다.
- 클라이언트가 보낸 피해량이나 명중 결과를 그대로 신뢰하지 않는다.
- 필살기 중 이탈·리셋이 발생해도 카메라와 이동 제한을 복구한다.
- 최초 구현 시 최신 Roblox API와 애니메이션 사용 조건은 공식 문서로 확인한다.

## 10. 컴퓨터 켰을 때 첫 실행 체크리스트

1. Roblox Studio에서 신규 Baseplate 프로젝트를 만들거나, 이미 만든 대상 프로젝트를 연다.
2. 이 파일을 개발 대화에 첨부하고 0번 시작 지시문을 보낸다.
3. 직접 연결 도구가 실제로 제공되는지 확인한다. 없으면 설치 가능한 파일 방식으로 진행한다.
4. 기존 프로젝트가 있으면 상태를 확인하고 백업한 뒤 수정한다.
5. 첫 목표인 임시 캐릭터 1대1 전투를 만든다. 모델 확보 때문에 전체 작업을 멈추지 않는다.
6. Studio에서 두 클라이언트로 테스트하고 실제 오류·영상·체감 의견을 공유한다.
7. 작업이 끝날 때 코드와 함께 적용 방법, 검증한 항목, 남은 작업을 갱신한다.
