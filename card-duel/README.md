# 카드 결투장

친구들끼리 겨루는 턴제 카드 배틀. 클로드 아티팩트 한 장으로 돌아가고, 순위표는 아티팩트 공유 저장소(`db`)에, 실시간 대전은 `room`의 presence로 동기화한다.

- **모드**: 솔로 도전(AI 3층 런) · 1:1 실시간 대전(도전장/빠른 대전) · 2:2 팀전(팀이 영웅 생명력 30과 전장을 공유, 빈자리는 AI)
- **카드**: 5파벌(불꽃·강철·비전·야생·그림자) + 중립, 수집 카드 76장. 파벌마다 영웅 능력. 덱 편집기(20장, 같은 카드 2장, 전설 1장)
- **순위** = 솔로 최고 점수(리플레이로 재계산해 검증) + 대전 승점(승 120 · 무 60 · 패 30, 상대 기록과 결과가 같을 때만 인정, 1:1 같은 상대 3경기 · 팀전 6경기까지)
- **이벤트**: 주최자(아티팩트 주인)가 30분~2시간으로 시작, 끝나면 최종 순위 확정

## 공정성 장치

- 엔진은 결정적(정수/사칙연산만)이라 같은 입력이면 어느 기기에서든 같은 결과. 솔로 기록은 시드 + 내 행동만 저장하고, 순위표를 보는 모든 화면이 다시 계산해 ✓/✗를 붙인다.
- 대전은 시작 때 덱+시드를 SHA-256으로 약속(commit)하고, 각자 행동 로그와 공개 상태 해시를 presence로 내보낸다. 해시가 어긋나면 즉시 무효. 끝나면 덱/시드를 공개하고 전원이 경기 전체를 다시 계산해 확인한다.
- 남의 손패는 '?'로 계산해도 공개 상태가 같게 유지된다(테스트로 매 단계 확인).
- 한계: 서버가 없어서 두 사람이 짜고 가짜 승패 기록을 맞춰 쓰는 담합은 막을 수 없다(같은 상대 3경기 상한으로 피해를 줄이고, 주최자가 기록을 지울 수 있음).

## 개발

```bash
npm run card:test    # 엔진 규칙 22개 + 솔로/대전/순위 로직 10개
npm run card:sim     # AI 대 AI 밸런스 (1:1, 2:2)
npm run card:build   # card-duel/dist/artifact.html (게시용 단일 HTML), harness.html (테스트용)
# 브라우저 시나리오(가짜 claude 런타임으로 탭 여러 개가 친구 역할):
(cd card-duel/dist && python3 -m http.server 4180) & node card-duel/test/e2e.cjs
```

카드 수치는 `src/cards.js`, 솔로 층 구성은 `src/solo.js`, 점수 규칙은 `src/standings.js`에서 바꾼다.
이벤트 중에는 다시 게시하지 말 것(엔진이 바뀌면 저장된 리플레이 검증이 틀어질 수 있음).
